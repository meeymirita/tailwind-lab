    🌊 Tailwind Lab — Pulse

    Tailwind CSS v4 с нуля на сервисе аналитики «Pulse»: маркетинговый лендинг, дашборд и страница настроек. Азбука утилит → тема через @theme → варианты и состояния → адаптив и container queries → тёмная тема, формы и переиспользование → продакшн. Стек: Tailwind CSS 4.3, Vite + @tailwindcss/vite, чистый HTML и немного JS.

    Как устроена лаба. Разделы 1–9 — теория: зачем Tailwind и когда он не нужен, как читать классы, что происходит под капотом v4, тема, варианты, адаптив, тёмная тема, переиспользование, структура проекта. Раздел 10 — шесть сессий заданий (~20 часов). В отличие от CSS-лабы, разметку вы пишете сами: в Tailwind стили живут в классах, и разделить их нельзя. Почти в каждой сессии есть шаг «сломать → починить»: динамический класс, которого нет в сборке; порядок классов, который ничего не решает; свой CSS, перебивающий утилиты; peer, который «не видит» чекбокс; dark:, не реагирующий на переключатель; @apply, падающий с «unknown utility». У каждого шага: код → «зачем» → команда → ожидаемый результат → «проверь себя». Разделы 11–14 — чек-лист, глоссарий, вопросы, что дальше.

    Отдельный репозиторий tailwind-lab, ни от одной другой лабы не зависит. Предполагается уверенное знание CSS: каскад, flex, grid, container queries, :has() — Tailwind их не заменяет, а записывает классами. Если CSS-лаба пройдена, в конце вас ждёт таблица сравнения. Все утилиты сверены с Tailwind 4.3; если в вашей версии что-то иначе — ориентируйтесь на tailwindcss.com/docs. Ответы на «проверь себя» — в docs/tailwind-notes.md.

    1. Зачем Tailwind — и когда он не нужен #

    Tailwind — это набор маленьких классов, каждый из которых делает одну вещь: flex, gap-4, text-lg, bg-brand-600. Вместо того чтобы придумать имя .pricing-card__header--featured и написать для него CSS, вы собираете вид прямо в разметке. Сборщик сканирует исходники и кладёт в итоговый CSS только те классы, которые встретил.

    Боль в «ручном» CSSЧто даёт TailwindЦена
    Придумывать имена классовимён нет — есть свойствадлинные class=""
    CSS растёт вечно: страшно удалятьудалили разметку — класс исчез из сборкистили «размазаны» по HTML
    Прыгать между HTML и CSSвид элемента видно в одном местеразметка хуже читается без привычки
    Магические числа, разнобой отступовограниченная шкала: p-4, а не 17pxшкалу нужно выучить
    Специфичность и порядок файловвсе утилиты — один слой, одна специфичностьконфликтующие классы на одном элементе (шаг 1.4)
    Повторение одинаковых блоков—решается компонентами шаблонизатора, а не CSS (раздел 8)

    Когда Tailwind не нужен или вреден: сайт-документ с контентом из CMS (стилизуется разметка, которую вы не пишете — там нужны обычные стили или prose, шаг 5.4); команда без понимания CSS (классы перебираются наугад так же, как свойства); проект без компонентной модели, где одна и та же кнопка скопирована в сорок файлов.

    ГЛАВНАЯ МЫСЛЬ ЛАБЫ Каждый класс Tailwind — это CSS-правило, которое вы могли бы написать сами. md:hover:bg-brand-600/80 — это «при ширине от 48rem, при наведении, фон — фирменный цвет 600 с прозрачностью 80%». Если в голове нет CSS, стоящего за классом, Tailwind превращается в угадайку. Поэтому в каждом шаге лабы — DevTools: смотрим, какой CSS сгенерирован.

    2. Азбука: как читается класс, шкалы, произвольные значения #

    2.1 Анатомия класса

      md:hover:bg-brand-600/80
  └┬┘ └─┬─┘ └┬┘ └──┬───┘└┬┘
   │    │    │     │     └─ модификатор: прозрачность 80%
   │    │    │     └─────── значение из темы: --color-brand-600
   │    │    └───────────── утилита: background-color
   │    └────────────────── вариант: :hover
   └─────────────────────── вариант: @media (width >= 48rem)

    Варианты читаются слева направо и складываются: dark:md:hover:. Утилита без вариантов действует всегда.

    2.2 Шкала отступов и размеров

    В v4 одна переменная --spacing: 0.25rem, а число в классе — множитель: p-4 = calc(var(--spacing) * 4) = 1rem, gap-6 = 1.5rem, w-72 = 18rem. Подходит любое целое: mt-13 тоже работает. Одна шкала для p-*, m-*, gap-*, w-*, h-*, size-* (ширина и высота сразу), inset-*.

    КлассCSSКлассCSS
    p-4 / px-4 / pt-4padding всё / inline / сверхуps-4 / pe-4padding-inline-start / end
    m-auto, ms-automargin auto / inline-start auto-mt-2отрицательный margin
    w-full, max-w-3xl100% / max-width 48remmin-h-dvhmin-height: 100dvh
    size-10width и height 2.5remw-1/250%

    2.3 Цвета и прозрачность

    Палитра по умолчанию — в oklch: slate, gray, zinc, red … rose, у каждого оттенки 50–950. Класс = свойство + цвет: bg-sky-500, text-slate-700, border-rose-300, ring-brand-500, fill-current. Прозрачность — через слеш: bg-black/50.

    2.4 Типографика

    text-sm … text-9xl — размер вместе с подобранной высотой строки; text-lg/7 — размер и line-height в одном классе. font-medium, font-bold, tracking-tight, leading-relaxed, text-balance, text-pretty, truncate, line-clamp-3, uppercase.

    Сканер ищет строки, а не выполняет код. Он не знает, что bg-${color}-500 превратится в bg-red-500: такой строки нет в исходниках, значит, нет и класса в сборке (шаг 3.4). Правило: класс в исходниках всегда пишется целиком.

    Что автоматически сканируется: все файлы проекта, кроме игнорируемых через .gitignore, бинарных файлов, CSS-файлов и lock-файлов. Добавить источник (например, библиотеку в node_modules) — @source "../node_modules/lib", исключить — @source not "./legacy", принудительно сгенерировать — @source inline("bg-red-500").

    Что такое @import "tailwindcss". Это нативные каскадные слои и три файла:

    @layer theme, base, components, utilities;
@import "tailwindcss/theme.css" layer(theme);         /* :root { --color-red-500: oklch(…); --spacing: 0.25rem; … } */
@import "tailwindcss/preflight.css" layer(base);      /* reset */
@import "tailwindcss/utilities.css" layer(utilities); /* все утилиты */

    Все утилиты лежат в одном слое utilities: .p-4 и .px-8 имеют одинаковую специфичность (0,1,0), и между собой они разрешаются порядком в сгенерированном CSS, а не порядком в атрибуте class. Tailwind сортирует правила так, чтобы сокращённые свойства шли раньше полных: px-8 всегда перебивает p-2. Всё, что вы пишете вне слоёв, сильнее любой утилиты (шаг 5.3).

    4. Тема: @theme — токены, из которых рождаются утилиты #

    @theme — особый блок: каждая переменная в нём одновременно становится CSS-переменной на :root и порождает утилиты по своему пространству имён.

    @theme {
  --color-brand-600: oklch(52% 0.14 215);   /* → bg-brand-600, text-brand-600, border-brand-600, ring-… */
  --font-display: "Inter Tight", system-ui, sans-serif;   /* → font-display */
  --breakpoint-3xl: 120rem;                 /* → 3xl: вариант */
  --radius-card: 1.25rem;                   /* → rounded-card */
  --shadow-card: 0 1px 2px oklch(0% 0 0 / .06), 0 8px 24px oklch(0% 0 0 / .08);   /* → shadow-card */
  --animate-fade-in: fade-in .3s ease-out;  /* → animate-fade-in */
  @keyframes fade-in { from { opacity: 0; translate: 0 4px; } }
}
    Пространство имёнУтилиты
    --color-*bg-*, text-*, border-*, fill-*, ring-*, shadow-* (цвет) …
    --font-*, --text-*, --font-weight-*, --tracking-*, --leading-*шрифты и текст
    --spacingвся шкала отступов и размеров
    --breakpoint-*, --container-*варианты md: и @md:, а также max-w-*
    --radius-*, --shadow-*, --inset-shadow-*, --blur-*rounded-*, shadow-* …
    --ease-*, --animate-*переходы и анимации

    --color-*: initial; внутри @theme удаляет всю палитру по умолчанию — дальше только ваши цвета. @theme inline { --color-surface: var(--surface); } — утилита подставит ссылку на вашу переменную, а не значение: так строятся темы, которые переключаются в рантайме (шаг 5.1).

    7. Тёмная тема: dark: по системе, по атрибуту, через токены #

    По умолчанию dark: — это @media (prefers-color-scheme: dark). Для ручного переключателя вариант переопределяют:

    @custom-variant dark (&:where([data-theme=dark], [data-theme=dark] *));

    Два подхода к цветам — их удобно сочетать:

    8. Переиспользование: компоненты, @utility, @apply, плагины #

    Главный вопрос Tailwind-проекта: что делать, когда одна и та же кнопка из двенадцати классов нужна в двадцати местах. Ответы в порядке предпочтения:

    СпособКогдаПример
    1. Цикл в шаблонеповтор в одном месте (карточки, пункты меню)v-for, @foreach, .map() — классы написаны один раз
    2. Компонент шаблонизатораповтор в разных местах<Button variant="primary"> во Vue, Blade-компонент <x-button> в Laravel
    3. @utilityодно CSS-свойство или маленький набор, которого нет в Tailwind, и он должен работать с вариантами@utility scrollbar-hidden { … } → md:scrollbar-hidden
    4. Класс в @layer components + @applyнет компонентной модели (чистый HTML, как в этой лабе), или стилизуется чужая разметка.btn { @apply inline-flex items-center … }

    @apply — последнее средство: он возвращает ровно то, от чего Tailwind уводил (имена классов, отдельный CSS, «где этот стиль»). В чистом HTML без шаблонизатора он оправдан — и в лабе используется именно для этого (шаг 5.3). Файлы CSS, которые обрабатываются отдельно от основного (стили компонентов Vue, CSS-модули, отдельно подключённый CSS), не знают вашей темы: им нужен @reference "../style.css";.

    Плагины подключаются в CSS: @plugin "@tailwindcss/typography"; — классы prose для контента из CMS или markdown; @plugin "@tailwindcss/forms"; — нормализация полей форм.

Для двух «равных» классов (bg-sky-600 и bg-rose-600) победитель определяется внутренним порядком Tailwind, и вам он неподвластен. Правило: не ставьте на элемент конфликтующие классы. В JS-проектах, где классы склеиваются из пропсов, для этого есть библиотека tailwind-merge. Суффикс ! добавляет !important — аварийный люк, а не инструмент.

    12. Глоссарий #

    Utility-first — подход, при котором вид собирается из маленьких однозначных классов в разметке.
    Утилита — класс, генерирующий одно правило: p-4, flex, bg-brand-600.
    Вариант — префикс, оборачивающий утилиту условием: hover:, md:, dark:, group-has-[…]:.
    Модификатор — суффикс утилиты: прозрачность /50, высота строки text-lg/7, имя группы /card.
    Произвольное значение — значение вне темы в квадратных скобках: top-[117px], grid-cols-[1fr_20rem].
    Произвольное свойство и вариант — [mask-type:luminance], [&_a]:underline.
    Сканер (Oxide) — часть движка v4, находящая в файлах строки-кандидаты в классы.
    @source — добавить или исключить (not) источники сканирования; inline() — сгенерировать классы принудительно.
    Preflight — reset Tailwind в слое base.
    @theme — блок токенов, порождающих утилиты и CSS-переменные.
    Пространство имён темы — префикс токена (--color-*, --breakpoint-*), определяющий, какие утилиты он создаёт.
    @theme inline — утилиты подставляют значение токена (например, var(--surface)), а не ссылку на переменную темы.
    @theme static — выводить в CSS все переменные темы, а не только использованные.
    @custom-variant — объявить или переопределить вариант (например, dark).
    @utility — объявить свою утилиту, работающую со всеми вариантами.
    @apply — вставить CSS утилит внутрь своего правила.
    @reference — дать отдельно обрабатываемому CSS-файлу контекст темы и утилит без вывода их в результат.
    @plugin — подключить плагин Tailwind из CSS.
    group / peer — маркеры предка и предыдущего соседа для вариантов group-* и peer-*.
    @container (класс) — сделать элемент контейнером запросов; @sm: и т. п. — варианты по его ширине.
    sr-only — визуально скрыть, оставив доступным для скринридера и клавиатуры.
    prose — класс плагина typography для стилизации контента без классов.
    tailwind-merge — JS-библиотека, убирающая конфликтующие классы при склейке из пропсов.
    Семантический токен (роль) — цвет по назначению (surface, fg-muted, line), а не по оттенку.
